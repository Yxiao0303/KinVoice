# 受预算保护的本地真实网页演示

新增`budgeted_web_demo.py`，仅监听127.0.0.1。复用生产页面、认证、流式API和Engine，
通过WebBudgetProvider将所有状态提取、生成和校验请求送入同一个持久账本。
模型固定为deepseek-flash，thinking关闭，每次最多400输出token；本演示关闭自动重写，提供器无自动重试。
账号存储为临时目录；模型配置仅来自已有安全绑定，不写入或打印凭据。

## 额度提升的审计约束

默认授权仍按原账本保存，不能因为新任务、新服务或新录制而初始化另一份额度。
在用户明确批准提高累计上限后，`approve_cumulative_50`只允许既有10元政策提升到累计50元，
不改变原授权ID、费率、有效期、token上界、历史尝试、用量估计或已预留金额。
审计表保留旧/新policy完整快照、批准引用和时间；新建50元账本、缺失审计记录、
未批准的引用、在途或未知状态都拒绝。该引用是操作审计标签，不是授权密钥或独立权限机制。
网页入口不会自行批准或迁移额度；供应商账户支出锁仍不在本地程序能力范围内。

## 演示限次与恢复

本轮网页演示单独最多9次，但费用仍与此前记录累计，不是另一个预算。
固定操作序号确保不能重复领取。重新启动默认拒绝已有演示尝试；只有显式
`--resume-within-cap`且此前所有尝试已结算、序号连续，才可从已用次数之后继续，
绝不把计数归零。未知用量、取消、无效格式按既有规则保留完整预留并冻结。
该恢复功能用于录制工具中断后的已知结果核验，不自动重试模型调用。

本地入口：`.venv/bin/python scripts/budgeted_web_demo.py`。
运行前必须在当前授权范围内，核验有效价格政策和规范账本；不能复制、清空或替换账本绕过保护。
离线入口`offline_web_demo.py`保持独立且明确标记mock；真实演示不会插入mock回复。

## 验证与局限

新增离线测试覆盖历史记录保持、额度提升审计、未批准/新账本拒绝、在途拒绝、
发送前原子预留、9次硬上限和恢复不归零。后端共140项通过。
录制工具失败不等于模型调用失败：先读账本核对是否已发生收费尝试，再决定是否继续。
录制文件及当前运行审计留在本地交付流程，不将对话、账号、环境标识或凭据发布到仓库。
一次虚构场景演示不能证明模型泛化、语义正确性或心理有效性；专业审核仍未完成。
