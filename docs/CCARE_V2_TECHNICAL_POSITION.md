# C-CARE 0.2：技术实现与创新边界

日期：2026-10-23。接口版本为 0.4.0，策略版本为 `ccare-prototype-0.2`。本文追加本轮状态，不替换早期核查与诊断记录。

## 结论

目前最值得集中表达的技术主张是：**证据绑定的亲子冲突支持策略控制**。把当前用户意愿、家庭不安全线索和可定位的原话证据交给确定性策略层，限制候选支持方式，再生成和校验回应。

这是已经实现的工程机制，也是待验证的方法假设。现有证据不足以宣称学术首创、效果领先或临床有效。网站、调用日志和错误提示能展示机制是否被执行；强基线、消融和专业盲评才决定它是否有价值。

## 一个决策怎样发生

输入包含本轮文字、最近对话和界面选择。状态估计生成风险、家庭线索、情绪及本轮支持意图。程序拒绝无法在用户消息中找到的引用；支持意图的引用必须来自本轮，避免历史意愿替用户作当前决定。字符位置以 Python Unicode 码点计数。

策略层先得到允许集合 `A`，再从中选择回应策略。紧急线索使集合仅包含安全模板；本轮明确拒绝建议使集合仅包含倾听；家庭不安全线索会排除沟通草稿。当前文本的明确需求可以修正界面选择，但不能越过这些约束。

可写成 `策略 ∈ A(风险线索, 家庭线索, 本轮意愿)`。当前实现为确定性规则，没有训练一个策略优化器。生成器接收选择结果和允许集合；校验不通过时重写一次，仍失败则给固定退回回应。前端只显示结构化决策与原话，不展示模型内部推理。

生成调用成功不等于回应被批准。阶段显示“调用完成”只证明收到返回；`checks`、最终 `mode` 和 `failure_code` 才说明校验与退回情况。失败退回时，`decision.selected` 保留原定策略，顶层 `strategy` 标识实际交付策略。

## 可以作为答辩主张的三点

### 核心机制：意愿与家庭安全约束进入策略集合

用户明确拒绝建议时，即使界面点了准备表达、模型也预测为草稿，策略层仍选择倾听。出现家庭不安全线索时，草稿从允许集合中排除。这比单纯在系统提示词里要求“尊重用户”更容易检查和消融，但优势尚未被真实模型实验确认。

**待验证假设 H1**：在相同基础模型、输入和调用上限下，该约束控制减少忽视拒绝与不合适联系建议，同时不会明显牺牲支持有用性。效果与可接受差异须在正式实验前由专业人员共同冻结。

### 可检查的依据：状态判断绑定原话位置

拒绝助手历史充当证据，拒绝引用不存在的句子；本轮意愿不能只引用历史文本。展示具体引用和触发规则，方便专业人员纠错。通用出处校验已有相关工作，这里只能把“亲子冲突中的证据接口与约束组合”作为候选贡献。

**当前限制**：字符串匹配仅验证引用存在。引用可能真实但不足以支持风险、情绪或意图判断；目前没有逐项证明语义蕴含，更没有临床标签可靠性的证据。

### 评测贡献候选：对同一情境做成对改动

保持情境主体尽量一致，只改“是否拒绝建议”“是否存在暴力/监控线索”或“用户选择的支持方式”。检查两端策略是否分别符合预期；另加无关背景变化，观察策略能否保持稳定。

本轮 8 对是开发数据，已经参与实现，标签来自开发者。它只能检查机制，不能作为独立模型测试。正式版本需专业审阅、按母案例隔离划分、保留反例与歧义；也要纳入与关系亲密、过度依赖相关的错误。

## 后续实验如何排，避免把更多调用当成创新

| 条件 | 作用 | 预算口径 |
|---|---|---|
| 单次强提示词基线 | 检查普通高质量提示词能做到多少 | 记录 1 次调用的实际 token、延迟与错误 |
| 多步强基线 | 控制拆步和额外调用带来的收益 | 同模型、同候选生成/检查机会、同最大 token 与总时限 |
| 完整 C-CARE | 测试约束控制的总体收益 | 与多步强基线对齐调用上限，实际调用另报 |
| 移除意愿约束、移除家庭约束、移除原话校验 | 分别识别模块贡献 | 在隔离评测器中消融；网站保持完整约束 |

各条件用同一冻结输入和随机顺序，评价者不知道条件。报告约束违反、支持有用性、危险遗漏、过度拒答、调用失败率及实际成本；不给失败样本补零成本，也不只展示通过案例。多轮与引用/否定/隐喻另分层报告。真人效果研究另设协议，不能从文本评测推断。

这些对照尚未运行。专业老师、新密钥与冻结数据仍是依赖。当前固定示例、模拟接口测试及成对开发诊断都不能证明 H1。

## 仍需正面披露的问题

- 本地危险关键词仍可能误报否定和课程转述。已知的两个漏报模式增加了回归规则，但这不代表覆盖了其他隐晦危机场景。
- 状态估计与校验可共用同一模型，错误可能相关；原话核验不能证明语义判断正确。
- 简单输出规则存在误拒和漏拒；策略分类正确不等于自然语言回复遵守策略。
- `deepseek-flash` 是可更新的服务别名。记录请求名与服务返回名仍不足以保证服务端权重冻结，正式比较应记录时间窗口并寻找可固定版本。
- 暂停停止本页接收；已送至服务商的请求可能继续。没有生产级存储、同意凭据、审计和多人部署验证。
- 当届比赛报名、格式与赛道提交要求还未重新核验。项目创新表述不等于符合正式参赛要求或必然获奖。
