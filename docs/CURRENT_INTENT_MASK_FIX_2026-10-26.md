# 当前意愿约束修复：离线开发回归（2026-10-26）

## 问题与边界

真实三臂探索暴露的问题是：C-CARE 选择了 listen，但允许集合仍包含 listen、clarify、ground、draft。原全消息词面判断把第三方、历史请求与当前拒绝混在一起；状态校验将意愿降为 unknown 后，策略没有保住当前明确约束。

本次在相同已见输入上离线复现并修复策略集合：当前明确“先听、不要建议”时 allowed=['listen']，emotion/support_intent 的 unknown 不被伪造为确定状态。这里区分三件事：模型状态估计、当前用户原话支持的动作约束、生成后输出校验。单纯 selected=listen（例如默认 UI 选择而没有明确当前限制）不自动删掉其他策略。

## 实现与取舍

`backend/app/ccare/intent_scope.py` 是可审计词面规则，不是训练得到的语义推理器。它遮蔽引号内容但保留字符偏移，区分有限的说话人、历史和当前子句，排除假设与否定请求；当前修改标记重新计算约束。意愿证据指向真正的当前子句，避免引用前文同名引号片段。

- “先听我说完然后再给建议”：当前仅倾听；后续明确“现在请给建议”恢复建议相关动作。
- “不要建议，但现在我想写段话”：承认明确修改，不形成永久禁令。
- “不是不要建议”、第三方引述、历史/假设请求：不单凭这些词串添加当前拒绝。
- 同一轮“不要建议，帮我写一段话”且没有明确修改：暂保留倾听约束，避免执行可能违背拒绝的动作。这是保守产品规则，需人工审核；不声称已消解真实语义冲突。
- 急性风险独立优先，家庭不安全仍限制联系相关草稿；unknown 不代表无风险。
