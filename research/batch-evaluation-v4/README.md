# 跨消息风险事件绑定：v4离线开发增量

**AI合成、开发者标准、未专业审阅。0收费调用；36候选未运行。** 原v1的72行mock及v2/v3失败记录不改，本版本单独冻结。目标仅关闭明确跨轮第三方已解除却被历史扫描重新报警的问题，不保证通用风险理解。

## 已实现与证据

原例：历史source=old“朋友说‘爸爸正在掐我’”，当前source=now“朋友已经安全到家”。以前urgent，现在unknown；只排除对应历史身体伤害span，保留事件及解除来源，不标ordinary/安全。

复用reviews.sources、digest、reduce_reviews及现有EvidenceLink、FieldAssessment；新增RiskEventBinding仅为请求内可重算结构，不另存长期画像或事件库。event_id由来源ID/来源摘要/精确span派生，记录subject、status、原证据、更新证据与修订版本。来源没有显式ID时沿用history:index；截断/重排历史可能改变ID，这是边界，不冒称持久稳定实体识别。

按用户消息顺序重放明确更新，助手文本不充当事实；已解除事件不会在下轮普通聊天重新激活。新事件新ID，不受旧解除影响。只有完整的同主体安全到达句才能更新唯一事件；多事件可由已有source-specific风险修订区分，但仍需独立当前文本证据。仅撤销risk标签不清除独立危险；撤回解除陈述会恢复未解除状态。旧确认记录被明确较新同事件更新标为superseded，不覆盖当前证据。

不同朋友保持不同subject，未解除事件仍有效。对代词、多事件或“另一位朋友”的歧义保留pending_resolution、unknown和原证据；必要时一个澄清加条件式安全支持，无外部调用。若同时存在自身急性危险/自伤/过量，仍优先急性处理。相关澄清入口对三臂相同，不归C-CARE独享收益。

## 开发验证

新增12项测试，覆盖同主体事件、证据偏移/摘要、复发、自身风险独立、不同朋友、多事件、模糊指代及零调用澄清、用户修订/撤回、伪造来源拒绝、解除延续与旧确认不复活。全量228项离线测试通过。开发诊断记录提供原请求、状态及每个绑定，非模型效果或专家评分。

## 可复现剩余边界

历史“朋友说爸爸正在掐我”（没有引号），当前“朋友已经安全到家”，仍urgent，开发者预期unknown。本版只把明确引用结构实例化为事件，没有用宽泛关键词切掉其它危险。它不能可靠处理无引号间接转述、多层引用、昵称别名、隐含时间、多人共享称呼或来源被截断的情况。相同“朋友”若实际换了人而文本没说明，规则也无法知道；不把唯一表面标签当现实身份保证。

family_unsafe仍沿用旧独立扫描，第三方伤害词可能导致保守联系限制；本轮未宣称解决所有策略误报。pending时risk未知仅反映当前性/主体不确定，保留记录并询问；其临床适当性需要专业审核。

下一步需要语义适配器对现有事件结构提供实体同一性、事件关系和证据span，并经过校验及专业标注；不能让LLM置信度直接清空安全历史。当前没有训练新模型或假称这一语义能力完成。

批量评测在代码、数据和协议冻结层面就绪，但真实运行仍依赖明确预算批准/审计迁移、有效价格策略和独立评分。400元尚未批准，不提前更改原20次调用和预留。无新页面、不合并部署。
