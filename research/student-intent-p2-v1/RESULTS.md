# P2 当前支持需求：真实 CPU 训练与一次探索评估

本轮确实训练了两个小型判别器，未接管应用。结论是**有限的可学习性与拒判取舍**，不是算法突破：32条训练样例拟合的字二元组模型在同一作者构造的16条候选上少错于现有作用域规则；但难例仍错，混合拒判降低接纳错误的同时遗漏一个明确请求。没有独立标签、真人数据、真实生成对照或初高中适用性证据。

## 已实现与复现

- 子任务：本轮明确支持需求四分类（listen/draft/clarify/unknown）。unknown 是信息标签，不是拒判；abstain 只是研究适配器不作建议，不自动触发追问，不代表无风险。
- 复用现有字符二元组特征；真实拟合多项朴素贝叶斯（alpha=1）与 L2 特征多类感知机。使用 Python 标准库 CPU，无软件/模型下载或 GPU；seed=20261026、25轮，词表、计数、权重、偏置、逐轮更新数完整保留。
- 数据60条、30个情境/模板家族：32 train（16家族）、12 dev（6家族）、16 candidate（8家族）；四类分别8/3/4条。全为同一 AI 助手手写合成、未专家审阅。没有借用旧36候选或旧v5输出。
- train/dev 完成后真实训练耗时约 **0.089秒**（一次观测，非性能基准）。方法、参数和 dev 阈值先冻结，然后构造 candidate、锁定、一次评估。本版没有按 candidate 结果调参或重报。
- 开发阈值0.25；暂定错误成本1、拒判成本0.25、最低coverage0.5。网格与全部开发指标见 `frozen/manifest.json`；分数差不是校准概率。混合阈值也用于 margin-only 消融，后者未单独调参，不视为各方法最优对决。
- ID与文本无完全重复、family/template_family不跨集合；跨集合最大字符三元组Jaccard=0.4545，小于冻结阈值0.85。近似对见候选锁。**不代表语义独立**：共享请求语法、同一作者和标签设计仍可能导致偏差。

运行阶段：`scripts/train_student_intent.py prepare` → 构造候选 → `lock` → `evaluate`。结果目录存在时拒绝覆盖。已完成的仓库只应 `verify`；复现训练可在测试中验证参数逐值一致，不删除原结果再跑。

```sh
.venv/bin/python scripts/train_student_intent.py verify
.venv/bin/python scripts/check_ccare.py
```

产物：`frozen/nb.json`、`linear.json`、`manifest.json`；`candidate-lock.json`；`results/predictions.json`（60×5条完整逐例预测）；`metrics.json`（含各集合混淆矩阵、覆盖/拒判、错误）；`receipt.json`（评估时间与输出哈希）。训练/开发结果仅诊断，候选也不是独立未见测试。

## 候选一次结果：每方法分母16

| 方法 | 全分母正确 | 接纳/覆盖 | 接纳错误 | 拒判 | 明确请求被拒判 |
|---|---:|---:|---:|---:|---:|
| 现有强作用域规则 | 11/16 | 16/16，100% | 5/16 | 0 | 0 |
| 训练朴素贝叶斯 | 14/16 | 16/16，100% | 2/16 | 0 | 0 |
| 训练线性感知机 | 14/16 | 16/16，100% | 2/16 | 0 | 0 |
| 选择性混合（规则+训练模型） | 12/16 | 12/16，75% | 0/12 | 4 | 1 |
| margin-only消融 | 14/16 | 15/16，93.75% | 1/15 | 1 | 1 |

混合方案没有在全分母正确数上胜过两个简单统计模型；接纳错误0/12不表示可靠概率或安全保证。三个unknown被拒判，不能把这三例算成正确unknown。unknown正确计数：规则/NB/线性/margin-only均4/4，混合1/4。覆盖减少和错误减少必须一起报告，不制造综合胜率。

## 可复核错误与归因

- `candidate-06-1`：“组会之后，帮我把想问的问题理一理，不要先写邮件。”开发标签clarify。NB误判draft，线性误判listen，规则unknown，混合及margin-only拒判。词袋/二元组不能可靠绑定“不要”的作用域与当前整理请求；拒判避错但没有完成所请求帮助。
- `candidate-08-1`：“作品集交完了。我之前想写说明，但现在只想倾听。”两个训练模型均unknown，未学会可靠的当前修订优先；规则给listen，混合由规则保留listen。该收益不能归功于训练模型。
- 规则在评图倾听/客气回复、微积分题目确认、来访倾诉、组会整理共5例漏掉未覆盖措辞，输出unknown；这说明规则召回有限，不证明小模型具备一般语义理解。
- 候选家族及标签由同一开发助手构造，且没有专业复核。“先弄清哪一题”和“理一理问题”是否都归clarify，以及拒绝方案是否足以归listen，仍需独立双人标注与分歧记录；本版保留原标签，不为结果调整。

## P1接口边界与反例

`ResearchIntentAdapter.propose` 只返回提案，不写 State/Policy；独立急性风险存在或用户修订存在时拒绝接管。未在 API/UI 导入此模型。针对P1原话/修订的测试继续验证：转述/历史睡眠词不变成当前本人影响；文字拒绝计划优先于小步骤菜单；卡片主体更正不被训练建议覆盖。

`p1-counterexample.json` 保留一条**未解决**的合成开发反例：“妈妈说我不努力”后自然语言更正“那句话是我爸说的”。P1仍保留两个active事件，旧事件未自动失效。卡片明确来源纠正可用，但普通自然语言跨轮事件归并尚未完成。本轮四分类训练不解决该问题，也没有篡改或重跑旧结果。
